# Coda-Score v0.3.0 终极架构方案：纯现代音乐 RAG 与局部图形生成

本方案基于最新共识，确立了一条**完全剔除古典乐理干扰、高度依赖专业代码排版、仅在必要时介入 AI 图像生成**的自动化现代乐谱流水线。

核心思想：**将大模型的“古典常识偏见”彻底抹除，用一本极其硬核的纯现代音乐字典（RAG）武装大模型生成绝对正确的 LilyPond 骨架；同时将扩散模型（SDXL/LoRA）从“整图全屏重绘”降级为“局部图形符号贴图器”。**

## 阶段详解与执行步骤

### 阶段 1：知识库建设与“反偏见” (Data & RAG DB)
**目标**：建立系统独有的“核心护城河”。
1. **纯正的现代语法字典**：知识库 (`knowledge/` 目录) 必须高度浓缩，按“音高、节奏、音色、结构、排版”五大维度建立 Markdown 文件。**禁止放入任何常规的古典乐理（如大小调体系、标准四分音符概念）**，防止大模型发生“向均值回归（Regression to the Mean）”的退化。
2. **代码片段库 (Snippets)**：存储针对现代音乐极高难度的代码块（如：12音序列生成矩阵、五连音嵌套三连音、微分音标记、图形化延续线等）。

### 阶段 2：Python RAG 注入与 LLM 对接
**目标**：用最低的成本，实现最专业的逻辑生成。
1. 编写一个 Python 脚本 (`generator.py`)，负责对接大模型 API。
2. 引入轻量级向量检索（如 ChromaDB）：根据用户的提示词，精准抽取知识库中对应的现代音乐规则与 Snippet。
3. 通过 **System Prompt (系统级提示词)** 强制给大模型定调：
   > *"你是一个极致的前卫现代音乐家。你必须忘掉所有调性知识与古典音乐习惯。严格套用我给你的规则与模板，拼装出 LilyPond 代码..."*
4. 此流程能彻底杜绝廉价模型的幻觉，保证出来的每一份代码都是出版级专业水准。

### 阶段 3：“占位符”与局部图形生成 (Local Graphic Inpainting)
**目标**：保全 LilyPond 完美排版的同时，赋予乐谱极端手绘/图形化能力。
1. 上一步生成的 LilyPond 代码已被系统自动编译为高精度的 PNG 乐谱。
2. 抛弃旧版“用 ControlNet 整张图过一遍”的做法（避免音符扭曲变形和算力浪费）。
3. **占位符机制**：当乐曲需要一段纯图形化的表达（如一片墨迹、特殊质感）时，大模型在代码中留出隐形的 `Bounding Box`（包围盒坐标）。
4. 系统捕捉到坐标后，单独调用 **SDXL + 现代技法 LoRA** 生成这一小块图形，并精准贴到 PNG 的空白处。

---

## 为什么这是最佳方案？

- **杜绝古典干扰**：通过精简且极端的 RAG 字典，防止 AI 不自觉地写出“好听且俗套”的古典和声。
- **降维打击的排版度**：由 LilyPond 负责 95% 的排版，生成的乐谱在五线谱、符干、音距比例上是绝对完美的，专业教授也挑不出毛病。
- **算力成本极低**：不仅 LLM 调用极度便宜，就连扩散模型也只需渲染局部小图（如 256x256），不需要每次跑 4096 级别的整张超分。
- **极强的可拓展性**：想让系统学会一种全新的前卫记谱法？只需要往 `knowledge/` 里丢一个新的 Markdown 规则文件，系统立刻掌握。
